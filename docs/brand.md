# AetherOS Brand Guide

This guide keeps the simulator visually coherent and OS-like for HCI demos.

## Product Tone

AetherOS should feel:

- calm
- fast
- technically credible
- purpose-built for system interaction

## Visual Direction

- Keep desktop and app surfaces clearly separated.
- Prefer soft depth, clean borders, and readable hierarchy.
- Avoid visual noise, cluttered controls, and overly saturated accents.

## Typography

- Primary UI: clean sans-serif stacks.
- Terminal/code areas: monospaced font (JetBrains Mono/Cascadia Code/Fira Code fallback).
- Keep small text readable; avoid decorative fonts.

## Windowing Language

- Lightweight windows with clear header/action affordances.
- Smooth open/minimize/focus transitions.
- Drag/resize should feel immediate and cursor-locked.

## Motion Rules

- Motion communicates state, not decoration.
- Keep durations short and consistent.
- Respect reduced-motion preferences.

## Desktop Rules

- Desktop must read as an OS environment, not a web dashboard.
- Keep icon placement and shell controls predictable.
- Reserve highest clarity for active windows and system alerts.

## Interaction Consistency

- Shared hover/active/focus behavior across shell controls.
- Notification actions must be explicit and reversible where possible.
- Empty/error states should be useful and concise.

## HCI Priorities

For coursework evaluation, prioritize:

- discoverability of system actions
- clear feedback loops
- predictable state transitions
- graceful recovery from errors

## Scope Note

Current brand implementation targets functional realism in-browser without copying any single commercial OS.
